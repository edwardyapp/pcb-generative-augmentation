# REPRODUCE

Every claim in the two papers, mapped to the exact command that regenerates it and the raw
file the number is read from. Commands assume the repository root as the working directory.

Read [AUDIT.md](AUDIT.md) alongside this file: it records an independent adversarial
verification of Table 1, the 10-seed paired test, the leakage controls, the synthetic-pool
counts and the filter identity, each with the command that re-checks it from raw artefacts.

**Read [§6 Where exact reproduction is not possible](#6-where-exact-reproduction-is-not-possible)
before comparing any number you regenerate against a published one.**

## 0. Prerequisites

| requirement | note |
|---|---|
| 2 CUDA GPUs | The pipelines pin `CUDA_VISIBLE_DEVICES=0` / `=1` and train the two priors in parallel. On a single GPU, run the two prior commands sequentially. |
| `PCB-cropped/all/` | The 10 668 source crops. **Cannot be regenerated here** — see §6.2. |
| `VOC_PCB/` | The VOC bbox annotations, needed for the tight crops. |
| checkpoints, `lmdb/` | Not in git (`.gitignore`: `checkpoint*/`, `*.pt`, `lmdb/`). Regenerated by the stages below. |

Stage 0 — the split and the base manifest — is a prerequisite for everything else:

```bash
python build_split.py            # -> results/splits.json, results/manifest.csv
python make_tight_crops.py       # -> results/manifest_tight.csv, results/manifest_tight_perbbox.csv
python make_budget_subsamples.py # -> results/manifest_tight_b{10,25,50}.csv, results/budget_subsamples.json
```

`build_split.py` fixes the board-level split: boards **06 + 09** are held out as test and are
touched by no classifier, no VQ-VAE, no prior and no filter. Every downstream script
re-asserts this.

## 1. Table 1 — A/B/C at every budget (the headline result)

The twelve numbers `A/B/C × {10, 25, 50, 100}%`, and the filter keep-rates.

```bash
./run_budget_pipeline.sh
# if interrupted (it is idempotent — every stage is skipped when its output exists):
./run_budget_pipeline_resume.sh
```

Per budget this trains the VQ-VAE from scratch on that budget's frozen subsample, extracts
codes, trains both priors from scratch (`--warm` is never passed), runs a conditioning check,
samples a 360-crop labelled pool, and runs A/B/C.

| output | field read for the paper |
|---|---|
| `results/abc_budget_b{10,25,50,100}.json` | mean over the 3 seed records of `[i]["A"\|"B"\|"C"]["macro_f1"]` |
| `synth_b{10,25,50,100}/` | 360 PNGs each, 60 per class |
| `results/cond_checks_budget.jsonl` | per-budget conditioning strength |

To recompute the published means from the raw JSONs without re-running anything:

```bash
python3 -c "
import json, statistics as st
for b in [10,25,50,100]:
    d=json.load(open(f'results/abc_budget_b{b}.json'))
    print(b, {k: round(st.mean([r[k]['macro_f1'] for r in d]),3) for k in 'ABC'})
"
```

Expected: `10 {A 0.419, B 0.431, C 0.433}` · `25 {0.641, 0.595, 0.632}` ·
`50 {0.804, 0.759, 0.814}` · `100 {0.899, 0.848, 0.884}`.

**Filter identity.** Condition C's filter is not a separate model: `abc_budget.py` trains the
Condition-A model and hands that same object to `filter_pool`, so the filter at budget *b*,
seed *s* **is** the Condition-A model at budget *b*, seed *s*. A synthetic crop is kept iff
that model predicts the class the prior was conditioned on. No confidence threshold.

## 2. The 10-seed paired test

```bash
python abc_b10_seeds.py --seeds 10        # or: ./run_b10_seeds.sh
```

Reads the frozen b10 subsample and the existing `synth_b10/` pool — it regenerates neither,
so it is classifier training only. Writes each seed to disk as it finishes and resumes from
whatever is already in the output file.

Output: `results/abc_budget_b10_seeds.json` (10 records, `seed` 0–9).

Recompute the test from the per-seed values:

```bash
python3 -c "
import json, math, statistics as st
from scipy import stats
d=json.load(open('results/abc_budget_b10_seeds.json'))
A=[r['A']['macro_f1'] for r in d]; B=[r['B']['macro_f1'] for r in d]
diff=[b-a for a,b in zip(A,B)]; n=len(diff)
m,sd=st.mean(diff),st.stdev(diff); se=sd/math.sqrt(n); t=m/se
tc=stats.t.ppf(0.975,n-1)
print('mean %.6f  t(%d)=%.4f  p=%.6f  CI=[%.6f, %.6f]' %
      (m, n-1, t, 2*stats.t.sf(abs(t),n-1), m-tc*se, m+tc*se))
"
```

Expected: `mean -0.008068  t(9)=-0.8107  p=0.438475  CI=[-0.030582, 0.014446]`.

The design is genuinely paired: the subsample is frozen, so seed *s* gives A_s, B_s and C_s
trained on identical data, differing only in initialisation. **Variance is over classifier
initialisation only, not over data subsampling** — this test cannot generalise over draws of
215 crops, and the paper does not claim it does.

## 3. The crop-scale comparison (Table 1 of the crop-scale paper, Tables 2–3)

The 600px baseline, the size-matched TIGHT set and the per-bbox TIGHT set, at four budgets ×
three seeds. Each run writes one JSON per (condition, budget, seed).

```bash
# 600px baseline            -> results/classifier_A_b{10,25,50,100}_s{0,1,2}.json
# TIGHT, size-matched       -> results/classifier_Atight_b*_s*.json
# TIGHT, per-bbox           -> results/classifier_Atightpb_b100_s*.json
for B in 0.1 0.25 0.5 1.0; do for S in 0 1 2; do
  python train_classifier.py --manifest results/manifest.csv \
      --budget $B --seed $S --condition A \
      --out results/classifier_A_b$(python3 -c "print(int($B*100))")_s$S.json
done; done
```

> **Reconstructed, not attested.** Unlike every other entry in this file, these exact
> invocations are **not** preserved in a committed run script. They are reconstructed from
> `train_classifier.py`'s argument parser plus the run headers in `logs/condA_sweep.log`,
> `logs/tightA_budget_sweep.log` and `logs/tight_sweep.log` (e.g.
> `[cond A_tight budget 1.0 seed 0] train=2149 test=518 test_boards=['06','09']`). Swap
> `--manifest`/`--condition` for the TIGHT variants. Treat the JSON outputs already in
> `results/` as the authoritative record.

Aggregate:

```bash
python3 -c "
import json, glob, statistics as st
for cond in ['A','Atight','Atightpb']:
    for b in [10,25,50,100]:
        fs=sorted(glob.glob(f'results/classifier_{cond}_b{b}_s*.json'))
        if fs:
            v=[json.load(open(f))['macro_f1'] for f in fs]
            print(f'{cond:9s} b{b:3d}  {st.mean(v):.3f} +/- {st.pstdev(v):.3f}')
"
```

Note `macro_f1` (final epoch) is the reported metric. These files also carry
`best_macro_f1` (best epoch, selected on the test set) — **it is not used in the paper** and
must not be quoted.

Figures: `python make_paper_figs.py`, `python plot_budget_abc.py`.

## 4. The binary track (defect vs no-defect)

```bash
./run_binary_track.sh        # -> results/abc_binary.json, synth_binary_*/
```

Trains unconditional priors (`--n_img_class 0`) on defect crops only, so every sample is a
positive by construction and no label can be wrong. Negatives are rejection-sampled windows
from the same 600px crops that miss every bbox (`results/manifest_nodefect.csv`). Covers the
honest (budget-restricted) and leaky (full-pool) generators at each budget.

## 5. Conditioning checks and the wiring control

### 5.1 Conditioning strength vs training epoch

```bash
./run_cond_checks.sh          # -> results/cond_checks.jsonl,  figures/fig9_consistency_vs_epoch.png
./run_cond_check_n360.sh      # -> results/cond_check_ep320_n360.jsonl + _pooled.json
python cond_check_n360_report.py
```

The n=360 replication is the one to quote: the earlier n=72 check at epoch 320 passed the
pre-registered collapse criterion, and the replication showed that pass was sampling noise.

These checks run on `pixelsnail_condtight3_*`, which is warm-started from a lineage
(`condtight2_080 ← condtight_060 ← pixelsnail_top_357`) that was trained on **all 10 boards,
test boards included**. That is sound for a *gate* — a leaked initialisation can only help
conditioning, so failing there is a stronger negative — but **no published A/B/C number
descends from it.** Every generator behind a published number is `prior_b*`, trained from
scratch with `warm=None` (AUDIT.md §3.3, §3.5).

### 5.2 Overfit-one-batch wiring control

```bash
python test_overfit_matrix.py | tee logs/overfit_matrix.log
# -> results/overfit_matrix.json, figures/fig13_overfit_one_batch.png
```

Memorises one crop per class in a top prior, then samples each class and compares the result
against **every** class's memorised grid. Reports teacher-forced reproduction (drift removed),
the 6×6 cross-class match matrix, diagonal/off-diagonal means, the separation, and how many
of 6 classes match their own example best.

Two scope limits, both recorded in the JSON and both of which the paper must state:

- **Reduced-capacity surrogate.** The model comes from `test_conditioning.build`
  (`channel=128, n_block=2, n_res_block=2, n_res_channel=128, dropout=0.0`), not the
  published prior (`channel=256, n_block=4, n_res_block=4, n_res_channel=256, dropout=0.1`).
  The conditioning *topology* is identical; the widths and depths are not.
- **Top prior only.** The bottom prior is not exercised by this script.

The related `python test_conditioning.py` covers both hierarchies but persists nothing beyond
the same PNG; prefer `test_overfit_matrix.py`, which now writes JSON.

## 6. Where exact reproduction is not possible

Three honest limits. None of them affects a published conclusion; all of them affect what you
should expect to see if you re-run.

### 6.1 Runs are not bit-deterministic (±0.004)

`set_seed` (`train_classifier.py`) seeds `random`, `numpy` and `torch`, but does **not** set
`torch.backends.cudnn.deterministic`, and the data loaders use `num_workers=8`. Re-running
reproduces published numbers to roughly **±0.004 macro-F1**, not exactly.

Measured instance: at budget 10, seed 0, Condition A is `0.405454` in
`results/abc_budget_b10.json` and `0.409410` in `results/abc_budget_b10_seeds.json` — same
data, same seed, same recipe, different run.

Consequence: verify published numbers against the committed JSONs (as AUDIT.md does), and
treat a re-run as a consistency check, not a bitwise one. Differences under ~0.005 are noise.

### 6.2 `PCB-cropped/` cannot be regenerated in this repository

The script that cut the original 600px crops from the raw HRIPCB boards ran on another
machine and was not preserved (`findings.md` §Finding 4). `PCB-cropped/all/` is therefore an
**input**, not a build product: every pipeline here starts from those crops.

What *is* reproducible from them: the board split, all manifests, the tight crops (recut from
the VOC bboxes by `make_tight_crops.py`), and everything downstream.

The crop geometry was nonetheless recovered post hoc from the VOC annotations, which is how
Finding 4 (defect position inside the 600px frame is effectively uniform-random; median 173px
from centre) was established without the original script.

### 6.3 `synth_b10`'s generating source is not provably byte-identical

`sample_pool.py` (mtime 2026-07-13 09:42:43) and `cond_check.py` (09:42:31) were modified
*during* the b10 sampling run, which started ≈08:23 and wrote its last file at 09:51:51. A
mid-run edit cannot affect an already-loaded Python process, and the mitigating evidence is
strong — the b10 log's output format matches the current `sample_pool.py` exactly, and all
four pools share an identical structure (10 chunks × 36, 60 per class, 360 distinct images).
But strictly, for `synth_b10` alone the source on disk is not *provably* byte-identical to
the source that produced it. `synth_b25`, `synth_b50` and `synth_b100` were all sampled after
the edit and are unaffected. Full detail: AUDIT.md §4.2.

### 6.4 Frozen subsamples — a design limit, not a defect

At each budget the data subsample is **frozen** (`make_budget_subsamples.py`, `DATA_SEED = 0`);
the 3 (or 10) seeds vary **classifier initialisation only**. Retraining 12 generators
(4 budgets × 3 data draws) was not affordable. Error bars are therefore narrower than a full
data-resampling study would give and must not be read as sampling error over subsamples.
Re-running with a different `DATA_SEED` will not reproduce the published numbers and is not
expected to.
